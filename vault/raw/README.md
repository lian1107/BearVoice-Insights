# vault/raw/ —— 客户原声原件

> **只读**：进来之后不改、不删、不重排。要加工，加工完的放 `vault/truth/`。
> **脱敏后的数据件直接入库**（仓库是私有的）——git 就是它的备份和版本历史，不用另外同步云盘。
> **前提是脱敏**：没脱敏的原始导出放 `_tmp/`，别搁这儿。

## 一、导什么（按可信度从高到低，也就是导入的优先顺序）

| 顺 | 材料 | 从哪导 | 为什么排这个位置 |
|---|---|---|---|
| 1 | **退货 / 售后维修记录** | 电商后台售后模块、售后服务商台账 | 真金白银投过票，最难造假，直接对应硬缺陷 |
| 2 | **追评**（用了一段时间才写的） | 天猫/京东 商家后台评价导出，注意勾上「追评」 | 比首评可信得多，暴露耐久性与真实使用场景 |
| 3 | **客服工单** | 客服系统导出（含会话记录最好） | 有上下文、能追问，但口径偏「安抚」，且**个人信息最密集** |
| 4 | **首评 + 社媒评论** | 后台评价导出；小红书/抖音笔记与评论区 | 量最大噪声也最大，只作量的佐证，不单独立论 |

> ⚠️ **挖新品概念时第 4 类要往上提。** 未满足需求不写在退货记录里——
> 退货只记录「买过的东西哪儿不行」，记录不了「他压根没买到的东西」。
> 社媒里的将就式表述（「我只好自己……」「拿 XX 凑合」「有没有那种……」）才是新品线索。
> 两套权重不冲突，因为问的不是同一个问题。

**格式**：一律导成 **CSV**。Excel 先另存为 CSV——xlsx 里的格式、公式、合并单元格不该进真相源。

## 二、怎么入库（两步）

```bash
# 1. 脱敏，写进批次目录（目录名：YYYYMMDD-来源-类型）
python3 scripts/desensitize.py ~/Downloads/天猫评价导出.csv -o vault/raw/20260815-tmall-追评/

# 2. 人工抽查两个文件，确认没有漏网的姓名和地址（见第三节），然后照常提交
git add vault/raw/20260815-tmall-追评/ && git commit -m "data: 天猫追评 20260815 批次入库"
```

拿不准会命中什么，先空跑一次看看，不写任何文件：

```bash
python3 scripts/desensitize.py ~/Downloads/天猫评价导出.csv --check
```

**批次目录命名**：`YYYYMMDD-来源-类型/`，例如
`20260815-tmall-追评/` · `20260815-jd-退货/` · `20260820-客服-工单/` · `20260820-xhs-评论/`

## 三、脱敏这件事，脚本做到哪、人接哪

脚本用**加盐哈希假名**替换，不是涂黑——同一个手机号永远得到同一个 `[手机-372a32]`。
这样才答得了「这三条差评是不是同一个人写的」，而跨 SKU 聚起来看，正是分辨
「一个人的怪癖」和「一群人的真需求」的唯一办法（意向书真难题第三条）。

| | 谁来做 | 说明 |
|---|---|---|
| 手机 · 身份证 · 邮箱 · 固话 · 订单号 · 快递单 | ✅ 脚本自动 | 正则可靠，已实测 |
| **收货地址** | ⚠️ **脚本只标记，人来删** | 中文地址正则识别不可靠，误删会把真相源弄残。脚本会把疑似地址打印出来，你确认后手动处理 |
| **姓名 · 店铺昵称 · 图片里的信息** | ❌ **脚本管不了** | 没有可靠特征。**抽查两个文件**是唯一防线 |

> **盐存在 `.env.local`，永不入库。丢了它，新批次和老批次就对不上号了**——
> 换机器时手动把这个文件带过去。

## 四、备份

提交并推送就完事了——私有仓，git 就是备份和版本历史。不用另外同步云盘。

例外只有大件：单文件 >50MB、xlsx 原件、截图包不进版本库（铁律 8），放本地或云盘，
仓里留一行说明它在哪。真遇到了再处理，别提前搭架子。

## 五、红线

1. **没脱敏的文件一律不进这个目录**——哪怕只是「先放一下」。
2. **原件只读**：入库后不修改。发现脱敏漏了，重跑脚本生成新批次，旧批次标注作废，不要就地改。
3. **不自建爬虫硬扛反爬**：优先用平台可导出的数据、公开可访问的页面（见意向书「不做什么」）。
4. 提交前扫一遍：`gitleaks detect --no-git --redact -v`
