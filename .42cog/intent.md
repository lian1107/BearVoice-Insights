# 小熊电器客户原声分析与产品改进挖掘 · 意向书

> 意向即行动。这一份文件决定这个系统会长成什么样。
> **只有一处必须你亲自过目：收敛方向。其余是草稿，看不顺眼再动。**
> **它现在一定是粗的。跑完 `-research` 会回来改——四步是循环，不是直线。**

## 这是一道赛题（2026-08-15 补，原件 `vault/raw/20260815-赛题资料/赛题书.md`）

**出题方**：小熊电器股份有限公司。**赛题**：用 AI 聚类分析客户咨询/评价原声，自动挖掘产品改进机会并输出改进建议报告。
**使用对象**：客服组长、客服主管经理、品控团队、客服数据运营。

**最低成果（达到任一项，企业即认可继续沟通价值）**：

| | 要求 |
|---|---|
| **A** | 现场展示**至少 1 个品类**的客户原声聚类结果（如 Top10 反馈类型及占比） |
| **B** | 输出**至少 3 条**可落地的产品改进建议（**含优先级排序**） |
| **C** | 展示改进建议生成的**工作流 Demo** |

**评价重点（出题方勾选）**：场景价值 · AI 应用深度 · 落地潜力。
**期望成果形式**：可演示 Demo · 产品/交互原型 · AI 工作流 · 解决方案 PPT · 技术路线说明。

> **这三项决定了什么算「做完」**——不是分析得多深，是这三样拿不拿得出来。
> A、B、C 全做到才有竞争力，但**先把 A 做扎实**：聚类结果是 B 和 C 的地基，地基虚了后面全虚。

## 收敛方向（唯一）

**把散落的客户原声，收敛成少而准的「产品机会」——向内是现有 SKU 改得动的缺陷，向外是原声里反复冒头、现有产品线接不住的未满足需求（新品概念 / 新品类）。每一条都带原话证据、指得到具体场景或部件、给得出下一步动作。**

> **两个出口，一条方向**：都是「从原声里挖出可执行的产品机会」。
> 收敛不在于只做一件事，而在于**判据只有一套**——拿不出证据、指不到场景、给不出动作的，两个出口都不收。

怎么算数：一条机会要计入产出，必须同时满足三件事——

| 判据 | 改进型（向内） | 新品型（向外） |
|---|---|---|
| **有证据** | ≥3 条互相独立的原声支撑 | ≥5 条互相独立、且来自不同人群/场景的原声 |
| **指得到** | 落到具体部件、参数或使用环节（「糊锅」不算，「加热盘中心温度过冲导致底部结焦」才算） | 落到具体人群 + 具体场景 + 现在他们只好怎么将就（「想要更方便」不算，「租房党没灶台，早上想煮一人份粥又不想洗锅，现在用泡面桶将就」才算） |
| **给得出动作** | 一个方向明确、成本可判断的改法（改结构 / 改参数 / 改说明书 / 改详情页预期管理） | 一个能判断可行性与差异化的产品概念雏形（形态 / 核心功能 / 为什么现有产品接不住） |

三者缺一 → 退回 `notes/`，不进 `reports/`。
**关联度 = 合格条目数 ÷ 提出条目数**，这个比例就是这个系统好不好用的唯一刻度。

## 真难题

三级过滤后剩下三条（前两条服务向内，第三条服务向外）：

**一、噪声里分不出「真缺陷」和「用错了」。**
差评里混着使用不当、期望错配（详情页吹过头）、物流破损、竞品水军。人能读，但读一万条就绕不过去；
一句提示语也判不准——判断需要品类常识 + 产品结构知识，模型默认会把所有差评一视同仁地当缺陷。

**二、从「客户原话」到「工程改法」之间那一跳。**
客户说「糊锅」，工程上可能是加热盘功率曲线、涂层附着、搅拌间隙、或者根本是用户没按说明放水量。
这一跳是这个系统真正的价值所在，也是 AI 默认会偷懒的地方——**它会停在复述客户的话，然后管那叫分析。**

**三、分不出「一个人的怪癖」和「一群人还没被满足的真需求」。**
这是新品方向的命门，也是最难的一条。难点有二：
① 真需求**往往不写在差评里**——人不会为一个还不存在的产品打差评，
它藏在「我只好自己想办法」「我拿 XX 凑合用」「有没有那种……」这类将就式表述里，正面情绪居多，常规差评分析会整批漏掉；
② 单条看都像个例，**只有跨 SKU、跨平台、跨时间聚起来才看得出是一群人**。
这一条多年反复投入仍没解决——所以它是真难题，不是活儿。

> 不是难题、别当难题办的：抓评论。一个导出工具或一段脚本就解决，不值得为它设计系统。

## 不做什么

| 不做 | 为什么不做 |
|---|---|
| 好评率 / 星级趋势看板 | 电商后台已经有，重复造，且看板不产生任何改进决策 |
| 竞品全景对标报告 | 竞品只在解释某一条具体机会时作为参照引入（「现有产品为什么接不住」），不单独成篇 |
| 舆情监控 / 危机公关响应 | 那是时效性任务，节奏和判据都和「产品机会」不是一回事，混进来会把系统拖成日报机 |
| 拍脑袋的新品创意 | 新品概念只从原声证据里长出来。**没有 ≥5 条独立原声支撑的点子，再好也不进 `reports/`** —— 这是新品方向唯一的护栏，松了这条，系统立刻退化成头脑风暴机 |
| 完整的新品可行性论证（BOM / 模具 / 定价） | 本系统只交付到「概念雏形 + 为什么值得做」。往后是工程与商务的活，判据完全不同 |
| 自建爬虫硬扛反爬 | 法务与维护成本高。优先用平台可导出的数据、公开可访问的页面 |
| 含个人信息的客服原始记录直接入库 | 手机号 / 地址 / 订单号必须先脱敏，脱敏前不进 `vault/` |

## 真相源：手上实际有什么（2026-08-15 实测）

**唯一一份**：`vault/raw/20260815-赛题资料/天猫咨询原声-1500条.csv`

| 维度 | 实际情况 |
|---|---|
| 渠道 | 天猫 **100%** |
| 类型 | **全部是「咨询」**（客服对话），**没有评价、没有退货记录** |
| 情感 | 中性 80.1% ｜ 负向 15.7% ｜ 正向 4.3% |
| 时间 | 2026-08-01 → 08-03，**仅 3 天** |
| SKU | 5 个：养生壶 487 ｜ 电饭煲 357 ｜ 内衣洗衣机 319 ｜ 抽水器 266 ｜ 破壁机新品 71 |
| 文本 | 中位数 26 字，47% 含多轮对话（`<br>` 分隔） |
| 个人信息 | **无**（`原声内容` 列实测零命中，数据已脱敏） |

### 这份数据的性质决定了分析方法，有三条必须写死

**一、只盯负向会漏掉大头。**
这是**咨询**不是评价。一条中性咨询「这个怎么清洗」本身不带情绪，
但它**重复出现几百次，就是设计缺陷或说明书缺陷**——用户需要问，说明产品没讲清楚。
80% 的中性咨询是金矿不是噪声。这一条直接对上赛题痛点②「重复问题没有归类汇总机制」。

**二、咨询量本身就是权重。**
没有退货数据来加权，但**问的人多少**就是影响面的代理指标。频次即优先级的第一维。

**三、3 天数据不足以谈趋势。**
不做时间趋势、不做「同比环比」——**样本期太短，任何趋势结论都是编的**。
只做截面聚类与占比。这是这批数据的硬边界，别越过去。

> 原先草拟的权重表（退货 > 追评 > 客服 > 社媒）**在这批数据上一条都用不上**——手上只有客服咨询这一层。
> 那张表留到真接入多渠道数据时再启用，现在不是真相源，是愿望。

## 作品区

- 目录：`reports/`
- 系统实际产出什么——**两类成品单元**：

| 类型 | 目录 | 一件成品长什么样 |
|---|---|---|
| 改进型 | `reports/improve-<品类>-<SKU>/` | 一张改进机会清单（按「改得动 × 影响面」排序）+ 每条机会的证据附录（原话摘录 + 出处） |
| 新品型 | `reports/concept-<主题>/` | 一份未满足需求的论证（这群人是谁 / 现在怎么将就 / 为什么现有产品接不住）+ 概念雏形 + 支撑原声全量附录 |

- **怎么算合格（验证闭环）**——**赛题场景下，判据就是最低成果 A/B/C**：

  | | 验收标准 | 现在的状态 |
  |---|---|---|
  | A | 至少 1 个品类的聚类结果 + Top10 反馈类型及占比 | 先做**养生壶**（487 条，样本最厚） |
  | B | ≥3 条可落地改进建议，**含优先级排序** | 优先级 = 频次（影响面）× 改得动 |
  | C | 改进建议生成的**工作流 Demo** | 管线要能当场跑给人看，不能只有结果 |

  **最终实效判据不变**：拿建议去问真正能拍板的人——「这个能改吗，改了大概多少成本」。
  被接住的条目占比才是真实效；全被打回「早知道了」，说明聚类停在了复述客户的话。
  ⚠️ 这一步是唯一不能交给 AI 的一步。
