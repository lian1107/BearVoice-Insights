# BearVoice 路演官方评审指南

## 一句话定位

BearVoice 是面向产品、品质、客服和经营团队的客户原声决策平台：它把“用户说了什么”转成“什么问题值得先处理、证据在哪里、还缺什么、由谁验证和改进”。

## 建议评审路径

1. 阅读根目录 `README.md`，了解商业价值、能力范围和架构。
2. 查看 `platform/frontend/src/pages/InsightsPage.tsx`，了解产品决策卡如何呈现风险、根因假设、改进方向和验证计划。
3. 查看 `platform/backend/src/bearvoice/modules/analysis/semantic_persistence.py`，了解逐条检查点、严格校验和原子发布。
4. 查看 `platform/backend/src/bearvoice/modules/reporting/decision_insights.py`，了解风险优先、多维切片和禁止结论。
5. 查看 `platform/frontend/e2e/real-compose.spec.ts`，确认浏览器测试使用真实 Nginx、API、PostgreSQL 和本地登录，不使用模拟数据。

## 演示中的关键页面

| 页面 | 评审重点 |
|---|---|
| 决策总览 | 当前最高安全优先级、去重分母、信号构成、Top 10 聚类和机会入口 |
| 产品决策洞察 | 多维切片、高价值模式、Top 决策卡、根因假设、改进方向、验证计划 |
| 产品机会 | 证据审核、负责人、协作人、行动状态和结果复盘 |
| 数据接入 | CSV 预检、字段确认、数据质量、模型选择和异步任务状态 |
| 主题治理 | 聚类命名与不可变版本修订 |
| 质量评测 | 人工黄金样本、发布门禁和模型回滚 |
| 系统状态 | 本地会话、OIDC 状态、模型外发批准范围和存储状态 |

## AI 深度不是“让模型写总结”

每条原声允许产生零到多个信号。信号契约包括：

- 信号类型和用户生命周期阶段；
- 对象、问题、场景与潜在需求；
- 必须来自脱敏输入的证据片段；
- 未校准置信度与风险等级；
- 待验证根因假设、缺失信息；
- 产品改进方向与可执行验证建议。

DeepSeek、GLM、MiniMax、通义千问和自定义兼容模型共用同一安全网关。模型外发默认关闭；开启时仍需 provider、purpose、HTTPS endpoint 三重 allowlist、隐私门禁、预算预留和逐次硬上限。

## 企业决策边界

- 样本覆盖不足 28 天，不做趋势、同比或环比判断。
- 没有销量、订单、退货、维修和成本分母，不计算发生率、损失金额或 ROI。
- AI 根因是待验证假设，不是已证实因果。
- critical/high 风险优先人工复核，但 AI 不自动决定召回、停售或发布。
- 所有行动结果为人工录入，不能单独证明产品改动造成了结果变化。

## 本地复现

```bash
cd platform
bash scripts/demo-up.sh
```

全新克隆没有完整历史缓存时，脚本会跳过基线导入，平台仍可启动；评审者可以在“数据接入”上传自有 UTF-8 CSV，并默认选择不调用外部模型的本地规则基线。

完整部署、安全、备份和模型配置见 `platform/README.md`。正式生产必须接入企业 OIDC、对象存储、网络出口和数据保留策略。
