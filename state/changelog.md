# 小熊电器客户原声分析与产品改进挖掘 · 演化记录（给人类）

> 每条只答三问：**变了什么 · 为什么变 · 对你意味着什么**。每里程碑一条，倒序追加；细节见 `state/board.md` 与 git log。

## 2026-08-15 · DeepSeek V4 Pro 深度洞察与受控批处理

**变了什么**：接入 DeepSeek、GLM、MiniMax、通义千问和自定义模型入口；外部分析升级为 Temporal 异步批处理、逐条检查点、有界重试和预算硬上限。信号增加生命周期、潜在需求、风险、根因假设、改进方向与验证计划，并新增产品决策洞察和行动结果闭环。

**为什么变**：原本的规则基线只能说明“有哪些反馈”，不能稳定回答“什么问题最值得先处理、为什么、该验证什么、由谁负责”；整批失败后从头调用也会重复计费。

**对你意味着什么**：370 条正式批次已全部完成并缓存，生成 537 个深度信号；安全风险优先进入人工复核，未解析和隐私异常不会被伪装成成功。后续网络失败只补跑缺失记录，自动重试不能越过已预留硬预算。

## 2026-08-15 · 路演发布文档与官方评审入口

**变了什么**：根 README 改为面向官方的产品入口，新增 `docs/ROADSHOW.md`，并统一平台启动、模型配置、数据口径、验证证据和生产边界。

**为什么变**：旧 README 是内部脚手架说明，且混用了 370/254/10/9 本地规则基线与 363/537 的 V4 Pro 快照，外部评审容易误解。

**对你意味着什么**：GitHub 首页现在能直接说明商业价值、真实验证、技术架构和风险边界；数据库、原声和 API Key 不随仓库分发。

## 2026-08-15 · 证据优先 UI 与任务型导航

**变了什么**：按已选定视觉稿重构整套界面，侧栏入口统一为“决策总览、产品机会、数据资产、主题治理、质量评测、系统状态”；首页新增真实 P0 风险焦点、Lucide 图标、Recharts 信号构成、搜索和移动端底部导航，机会审核与证据抽屉同步统一视觉。

**为什么变**：原界面所有卡片权重接近、入口名称偏系统术语，移动端导航会横向拥挤，长机会文本和运行 UUID 又抢占阅读注意力；这会掩盖最需先处理的安全风险。

**对你意味着什么**：现在打开系统先看到玻璃壶身开裂/召回评估 P0，再看指标、信号和主题；入口按实际工作任务命名，桌面与手机均可直接操作。真实 Compose、自动化测试和设计 QA 已通过，GitHub 推送仍按你的安排稍后进行。

## 2026-08-15 · 驾驶舱统一为单一产品决策视图

**变了什么**：删除“赛事视图 / 企业视图”切换，同时移除前后端没有业务差异的 `view` 参数和返回字段；测试与设计文档统一改为产品决策驾驶舱。

**为什么变**：浏览器实测确认两个入口加载完全相同的 370/254/10/9 数据和组件，仅按钮选中态变化；保留会暗示两套产品或两套数据口径。

**对你意味着什么**：首屏直接进入唯一、可审核的决策驾驶舱，数据边界、证据下钻和治理入口均保留；赛事展示仍可使用同一页面，但不再作为产品内概念暴露。

## 2026-08-15 · 企业平台架构审查与失败关闭硬化

**变了什么**：Temporal Activity 从无条件返回成功改为逐阶段核验真实数据库产物和幂等账本；数据库增加审计不可变、重复导入、黄金样本顺序与单 active 模型发布硬约束；补齐生产 readiness、应用级数据库配置、容器健康与自愈、同源写校验和浏览器安全头。

**为什么变**：原实现能证明组件骨架和真实数据页面，但工作流可能在没有真实产物时显示成功，关键并发与审计规则也只靠应用约定；这会在企业接入后放大为错误发布、不可追责或错误接流量。

**对你意味着什么**：本地纵向链路现在不仅“能跑”，还会在真实产物、配置或依赖不满足时明确失败；正式 SSO、生产网络、对象存储、跨产品线数据范围和保留任务仍需企业接入，不能把本轮硬化误称为生产上线完成。

## 2026-08-15 · 浏览器真实数据链路修复

**变了什么**：Nginx 新增同源 `/api/` 代理，Compose 服务改为仅绑定本机；新增只在开发环境和 localhost 开放的短期 HttpOnly 登录会话，并增加一条不模拟 API 的真实 Compose 浏览器测试。

**为什么变**：原浏览器测试拦截了所有接口，掩盖了生产 Nginx 把 `/api/` 返回成 HTML、后端又没有可用浏览器登录入口的问题；组件通过不等于真实部署可用。

**对你意味着什么**：现在浏览器可以显式建立本地安全会话，并经 Nginx、真实 API 和 PostgreSQL 看到 370/254/10/9；以后同类部署断链会由真实栈测试直接阻止提交。

## 2026-08-15 · 企业产品机会纵向链路完成

**变了什么**：把养生壶 10 个既有缓存以零模型调用导入统一数据库，贯通证据、人工审核、机会、行动和兼容 Markdown 导出；新增本地安全对象存储、企业 S3 端点边界、许可证清单及启动、恢复、备份手册，并在真实 Compose 环境启动数据库、迁移、API、Worker、Web 和 Temporal。

**为什么变**：企业平台不能只在测试替身或浏览器模拟里成立；数据迁移、审核写入、耐久工作流、恢复和报告兼容必须共用同一真相源，并能在实际容器中重复运行。

**对你意味着什么**：详细实施计划的 11 个任务已全部完成，本地已有一条可演示、可审计、可恢复且默认不外发模型数据的养生壶纵向链路；正式 SSO、生产 Kubernetes、PLM 和新增数据源留到企业接入阶段。

## 2026-08-15 · 可审计的人工治理工作区

**变了什么**：新增证据抽屉、分类法五类不可变修订、机会三类审核、负责人/外部任务衔接和黄金样本双人定标界面，并补齐真实写 API、事务提交与审计时间线。

**为什么变**：可点击的浏览器原型不能代替企业闭环；审核必须在真实数据库中保留操作人、理由、证据与版本关系，待审核模型结果也不能被界面误称为黄金答案。

**对你意味着什么**：品控、产品和模型审核人员现在能在同一平台核对脱敏原声、修订聚类、决定机会并定标样本；所有关键决定可追溯且不会覆盖历史版本。

## 2026-08-15 · 可演示、可下钻的决策驾驶舱

**变了什么**：新增赛事/企业双视图、六入口权限导航、KPI、四类信号构成、Top10 横向排名、机会列表、来源质量和只读系统状态，并完成桌面与手机端到端截图验证。

**为什么变**：企业 API 只有进入清晰、可操作的决策界面，才能同时满足赛事展示与内部日常使用；三天单渠道边界必须与数字同屏，避免把截面误读为趋势。

**对你意味着什么**：养生壶 370 条原声的赛事成果已有可点击界面，聚类和机会可继续进入人工治理；数字仍由统一 API 计算，不会另造一套前端口径。

## 2026-08-15 · 数字可对账、证据可下钻的企业 API

**变了什么**：产品驾驶舱 API 同时返回绝对数、占比、分母、来源和时间边界，并提供脱敏证据下钻、来源质量、分类法、机会、评测与系统状态接口。

**为什么变**：清晰图表的前提是数字口径唯一且能回到原声证据；若为了不同展示场景另算一套，长期必然漂移。

**对你意味着什么**：前端可以直接使用同一真相源展示赛事成果和日常管理信息；对任何机会或聚类数字的质疑，都可回到脱敏原声和分析运行。

## 2026-08-15 · 默认拒绝的企业安全边界

**变了什么**：建立 OIDC 身份验证、角色权限和产品线范围校验，同时建立默认关闭的模型外发网关、提供商/用途白名单和外发前隐私检查。

**为什么变**：私有化不等于所有内部数据都可随意流转；长期系统要同时防止人员越权和未批准的客户原声外发。

**对你意味着什么**：不同产品线和职能可共用平台而不互相穿透；未完成管理配置时，系统会拒绝模型调用，而不是将数据静默送出。

## 2026-08-15 · 人工定标的质量中心

**变了什么**：从养生壶真实基线入库 100 条分层待标注样本，并建立双人独立审核、第三人仲裁、四项确定性发布门禁和可审计回滚。

**为什么变**：已有模型结果只能帮助分层，不能自己证明自己正确；特别是安全类漏检不应被平均分掩盖。

**对你意味着什么**：小熊审核者完成首轮定标后，平台才拥有可信的评测标尺；以后更换模型、提示词或规则时，有确定的放行、阻断和回退依据。

## 2026-08-15 · 可追溯的机会决策与行动闭环

**变了什么**：新增不可变分类法修订、机会证据门槛与人工审核、安全优先级覆盖、行动负责人和结果/局限回收，所有关键决定均生成审计事件。

**为什么变**：企业长期使用不能只给出一次性排名；分析口径要能复现，机会要能说清证据和决策理由，行动要能验证是否真正改善。

**对你意味着什么**：小熊内部可在同一系统中从原声证据追到机会审核、执行负责人和实际结果；安全风险不会被低声量埋没，也不会绕过人审。

## 2026-08-15 · 可恢复且有人审的分析工作流

**变了什么**：新增 Temporal 九阶段耐久工作流、失败重试幂等键、人工审核暂停/恢复信号，以及结构化且先脱敏的失败诊断与最小追踪属性。

**为什么变**：企业分析任务可能中断、重试或等待跨部门审核，不能依赖一次进程跑到底，也不能为排障把客户原文、提示词或凭据写进日志。

**对你意味着什么**：长任务中断后可从已完成阶段继续，抽取失败不会换一套输入重复记账；分类法发布前始终保留明确的人审关口。

## 2026-08-15 · 养生壶验证基线进入平台

**变了什么**：10 个既有抽取缓存以严格只读模式迁入平台数据库，对账得到 370 条原声、370 条信号、254 条可行动信号、10 个聚类和 9 条待审核机会；CSV 接入同时固化了去重、隐私门禁和幂等协议。

**为什么变**：既有结果是节省重复抽取成本的验证基线，但不能因为缓存缺失静默调用模型，也不能把地址等个人信息带入长期数据资产。

**对你意味着什么**：平台已有真实养生壶证据可继续做聚类治理和机会决策；重复迁移不会重复记账，缓存不完整时会明确停止，而不是产生一套来源不明的新结果。

## 2026-08-15 · 企业领域与数据库真相源

**变了什么**：用 PostgreSQL/pgvector 和 Alembic 建立 22 张统一核心表，覆盖从数据来源、原声和多信号，到分类法、产品机会、竞品证据、执行结果、黄金样本和审计事件的全链路。

**为什么变**：长期使用不能让 Markdown 报告或一次性脚本成为事实正本；领域规则、数据库约束和可回退迁移必须共同定义唯一真相源。

**对你意味着什么**：后续养生壶历史结果和未来淘宝等来源将进入同一证据模型，可被下钻、复核和持续迭代，而不是各自生成无法对账的报告。

## 2026-08-15 · 企业平台可重复运行骨架

**变了什么**：新增经批准的 `platform/` 顶层协议，建立锁定依赖的 FastAPI 后端、React 前端、非 root 生产镜像与 PostgreSQL/pgvector、Valkey、Temporal 的本地私有化编排；模型外发默认关闭。

**为什么变**：长期企业平台必须先有可复现、可测试、默认不外发数据的运行地基，后续的数据治理、机会审核和评测闭环才能建立在同一真相源上。

**对你意味着什么**：平台已从设计进入可运行实施；本机可构建并启动前后端生产镜像，下一里程碑将把统一领域模型和数据库迁移接入这套骨架。

## 2026-08-15 · 企业私有化五项地基设计

**变了什么**：平台定位从一次性原声分析和报告，升级为小熊内部私有化的产品机会决策平台；设计规格统一了证据、分析、审核、机会、执行和模型评测闭环。

**为什么变**：赛题要求场景价值、AI 应用深度和落地潜力，长期企业价值也取决于机会能否被审核、认领和验证，而不是图表或报告数量。

**对你意味着什么**：后续不另做临时 Demo；在企业目标架构上先贯通养生壶真实链路，书面规格经人复核后再进入测试驱动实施。

## 2026-08-15 · 养生壶首份分析报告

**变了什么**：复用 Claude 已完成的 370 条抽取缓存，由 Codex 接续完成 10 类聚类、9 条改进建议和首份报告；新增重复口径与地址证据过滤回归测试。

**为什么变**：Claude 在聚类阶段因认证失效中断，且原报告生成逻辑混淆了重复 ID 与重复行，并漏过一段地址型文本。

**对你意味着什么**：赛题成果 A、B 和命令行工作流 C 已有一套可复核样稿；先核查玻璃炸裂安全项和聚类口径，再决定是否扩展到其余 4 个品类。
